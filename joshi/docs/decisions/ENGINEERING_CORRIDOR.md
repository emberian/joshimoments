# Engineering decision and delivery corridor

Status: **historical narrow corridor; partially superseded by `docs/implementation/PROGRAM.md`**.

This document reduces the engineering research into the smallest sequence that can decide the
stack and attempt natural use before September without lowering evidence or safety standards.

The later broad-base program preserves this document's exactness, replay, crash, provenance, and
no-economic-authority gates, but supersedes its exact-mint-first product scope, its assumption that
provider acquisition remained unauthorized, and its maximum-two-editor sequencing. Joshi now
advances isolated glass, Rust core, data, analysis, licensed-provider, and authenticated companion
lanes in parallel under explicit path ownership.

## Two parallel clocks

### Clock A: product/source Spike 0

Observe three ordinary Pump/Padre sessions, select one actual discovery-to-coin workflow, inventory
the material cues, classify every proposed acquisition operation, and select one mode:

- replacement-capable for one audited surface;
- reviewed companion;
- independent on-chain observatory;
- exact-mint/manual nomination only; or
- stop/rethink.

No automated Pump or social capture begins from architectural enthusiasm. The exact operation must
be cleared first. Clock A gates adapters and claims, not the offline core decision.

### Clock B: Decision Spike E0

Give the provisional Rust/TypeScript/SQLite stack one continuation-ready working day against a
fixed offline fixture. E0 makes no network call and contains no credential, builder, signer, or
broadcast dependency.

If Rust fails because of core build, dependency, bridge, or semantic friction, give a TypeScript
local-core fallback half a working day against the same trace. Do not build two full applications.
If neither closes the trace, retain the fixtures and reduce the product to a static exposure/scene
prototype rather than expanding the framework.

## E0 fixed fixture

The hand-readable semantic trace includes:

- duplicate delivery of one source event;
- two equal-valued but distinct chain effects;
- one unknown source variant;
- one gap and recovery;
- one late correction whose event time predates its availability;
- one partial realization and retained runner;
- exact flat, a watching-flat interval, and re-entry with a fresh basis epoch;
- one unknown-basis incoming quantity;
- an idempotently retried operator mark;
- one witnessed scene and later retrospective evidence.

The protocol trace contains one reviewed Pump native-SOL fixture, one curve quote, one PumpSwap
fixture if available without widening the day, integer boundary/refusal vectors, exact artifact
pins, and one opaque future variant.

The load smoke contains 50,000 representative envelopes with measured payload-size classes,
duplicates, large payloads, unknowns, and explicit source keys. It is a writer/queue smoke test,
not a market simulation.

## Required walking path

```text
fixture bytes
 -> bounded ingest
 -> durable raw observation/blob and acquisition identity
 -> atomic cursor/coverage commit
 -> versioned assertion or visible quarantine
 -> exact wallet and episode projection
 -> versioned query snapshot
 -> React exact-mint/episode view
 -> idempotent mark and scene receipt
 -> witnessed replay from stored view
 -> distinct retrospective replay digest
```

Rust is selected only if the path:

1. builds from a pinned stable toolchain through one documented command on Ember's ARM Mac;
2. reports a safe fixed SQLite runtime and verifies WAL/FULL, foreign keys, and strict behavior;
3. cannot advance a cursor beyond missing evidence;
4. survives kills around evidence/cursor and scene receipt without a false success;
5. reproduces the semantic digest and all fixture distinctions on two fresh replays;
6. rejects release-profile overflow and matches the pinned supported protocol vector exactly;
7. crosses the browser boundary without JavaScript monetary-number coercion;
8. completes the 50,000-envelope smoke with bounded memory, a draining queue, no unexplained loss,
   and no gesture delayed over 250 ms;
9. exposes intelligible lineage for the displayed value and scene; and
10. contains no economic-authority surface in its code or dependency graph.

Any unexplained one-atom protocol mismatch makes that lifecycle/formula `unsupported` or
`unquotable`; it does not justify averaging or selecting the favored SDK.

## Slice 1R: exact-mint truth corridor

If E0 passes, continue directly into the first natural-use slice. Ember can open or paste an exact
mint and see:

- exact current quantities for the smallest declared portfolio domain;
- RADON, EarthCoin, and CRASHIUS as the initial runner/exposure fixtures where chain evidence
  supports the relationship;
- honest realized/basis quality, leaving unresolved history unknown;
- a genuine event-backed chart with source coverage;
- a size-specific executable liquidation observation, or `unquotable` with the exact reason;
- coarse marks that do not force a final disposition taxonomy;
- external wallet changes as independent financial facts;
- an episode rail that keeps a coin alive while watching flat;
- witnessed replay and a visibly distinct retrospective view;
- source health, freshness, gaps, and provenance on every material field.

The UI remains post-selection until Clock A selects a discovery mode. Paste-mint episodes may study
management, exposure, and re-entry. They may not estimate Pump selection uplift or market-wide
scaling.

The slice passes when one ordinary session is naturally useful, exact balances reconcile or expose
named residuals, one consequential mark receives exactly one durable receipt, and a witnessed scene
replays recognizably without later knowledge.

Fallbacks preserve truth:

- unavailable quote: show `unquotable`, never a mark multiplied by bag size;
- missing historical basis: show exact current quantity and a basis gap;
- ambiguous episode attribution: retain the financial fact without a story;
- unsupported venue/lifecycle: show unsupported and use another natural supported mint;
- no cleared live source: keep the complete offline demonstration and manual exact-mint shell,
  without calling it natural market use;
- repeated clerical avoidance: stop platform expansion and retain the exposure prototype.

## Capacity gate after first use

The one-million-envelope test occurs once in the chosen stack after the runnable slice exists and
before broader continuous capture. It uses representative payload sizes and exercises:

- capacity-4096 bounded ingress and slow-sink injection;
- checkpoint/resume and canonical replay;
- browser reconnect over real view deltas;
- ten representative crash schedules;
- queue, latency, RSS, CPU, disk, WAL, and backup/restore behavior;
- exact accounting for parser rejection, duplicate, conflict, sampling, and gaps.

The 25,000-frames/s multi-language contest is deferred until an approved full-census workload
exists. The initial target is the measured selective scenario: approximately 10–50 events/s while
active, 200/s short bursts, no P0 loss, and explicit degradation everywhere else.

No `shitcoims_*` package is imported by the new runtime. Each donor is one fixture, pure behavior,
or UI pattern with old path/commit provenance, sanitization, new fixture hash, and an explicit
allowed claim.

Priority donors are:

positions, FIFO-as-universal-meaning, live executors, LP builder/signer code, background social

no product schema.

## Non-gameable rules

- Access admissibility precedes source architecture.
- Hard semantic gates precede weighted language preference.
- Freeze fixtures, holdouts, failure injections, budgets, and fallback before implementation.
- Every contender receives identical raw input and must produce the same end-to-end artifact.
- Sidecars, generated bindings, setup, and supervision count in a candidate's cost.
- Protocol oracles must declare ancestry; shared SDK descendants count once.
- Benchmark the production binding, filesystem, sync, blob, index, browser, and crash path.
- Introduce a later schema drift, missingness variant, accounting correction, and crash case before
  declaring the selected stack maintainable.
- Natural use is a veto, not another weighted score.
- Uncertainty narrows the displayed claim; it never becomes a proxy value.
- September removes features, never exactness, source health, no-send, or honest unknowns.
- A tie chooses the smaller currently useful path; it never keeps two cores.

## What may survive failure

Even if replacement, Rust, SQLite, natural use, and every strategy hypothesis fail, retain:

- the source/access and privacy dossier;
- language-neutral raw and adversarial fixtures;
- exact current quantities and named reconciliation gaps;
- quote/conformance vectors and honest unquotability;
- runner and exit–flat–re-entry fixtures;
- one append-only scene and recognized witnessed view;
- protocol ancestry and mismatch reports;
- storage/cost/recovery measurements.

That is a useful exposure instrument and a much better basis for the next decision than another
trading bot rewrite.
