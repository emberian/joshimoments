# JOSHI implications, study lanes, and promotion gates

## 1. What this formalization changes

The field language is useful only if it makes the apparatus more exact and more falsifiable. Its
concrete contribution is a set of seams:

```text
landed atomic conservation
  -> protocol-native state and exact quote geometry
  -> replayable descriptive measures over events/bins/graphs/attention
  -> fitted response, hazard, and memory operators
  -> explicitly latent equivalence classes
  -> prospective operator assistance or policy
```

This order rejects two equal mistakes:

- studying a pale scalar projection and declaring the whole composite process null; and
- wrapping intuition in field/physics vocabulary and declaring structure before measurement.

## 2. Minimum evidence additions

The existing evidence tape already supplies most primitives. A future field artifact should be a
versioned derivation, never a new raw truth table.

### 2.1 `DomainManifest`

```text
domain_id and topology version
domain kind: accounts | venue_state | bins | size_axis | event_marks |
             wallet_graph | social_graph | territory | attention_funnel | episodes
members/edges and point-in-time membership evidence
coordinate and reference measure
asset/venue/lifecycle scope
valid and known intervals
```

### 2.2 `BalanceArtifact`

```text
boundary manifest
asset identity
pre/post canonical observations
internal and boundary-crossing postings
mint/burn/conversion classifications
exact residual and unresolved evidence
profile/parser/reconciler version
```

### 2.3 `VenueGeometryArtifact`

```text
venue/profile/state closure
native coordinates and validation result
direction and exact size grid
quote/refusal surface with fee components
exact versus approximate representation
conformance grade and discrepancy fixtures
```

### 2.4 `MarkedFieldArtifact`

```text
eligible event universe and mark function
clock/event order
coverage manifest and gaps
aggregation/coarse-graining rule
value unit/reference measure
exact source inputs and production cutoff
uncertainty, topology changes, and residuals
```

### 2.5 `ConstitutiveEstimate`

```text
target field/transition
state/history inputs and availability cutoff
model/operator family
training/validation chronology
simple baseline and negative controls
calibration/error/support
gauge/equivalence sensitivity
falsifier and current status
```

### 2.6 `LatentExplanationSet`

```text
latent question
compatible mechanisms/topologies
evidence and assumptions per mechanism
observational equivalences
prospective discriminating probes
unsupported and contradicted cases
model/resolver/interview versions
```

No schema needs literal classes with these names immediately. They are semantic closure
requirements for whatever relations/artifacts carry the information.

## 3. Glass that earns its pixels

### 3.1 Native geometry panel

For the current venue, show exact native state rather than one generic depth blob:

- Pump virtual/real reserve and completion/capacity boundaries;
- PumpSwap raw/effective reserve and fee/payout boundaries;
- Meteora exact bin inventory, active bin, position shares, and traversal direction;
- route availability and state/quote age; and
- mark, intended-size quote, full-liquidation quote, and last fill separately.

An optional smooth curve may overlay exact points, with approximation error visible.

### 3.2 Conservation residual panel

For portfolio, position, and recent transaction boundary:

```text
atomic inflow/outflow by asset
fees/rent/rewards/withheld/unknown
internal custody movement
pre/post balance closure
unexplained residual
```

This panel is useful even if every strategy is negative.

### 3.3 Marked-flow strip

Separate tracks for:

- signed base and quote atoms;
- trade count and unique direct-user wallets;
- LP adds/removes and route changes;
- launch/migration events;
- social/callout/creator/claim events;
- product rank/viewport/open/arm events; and
- exact coverage/hot-scope boundary.

Never collapse them into one pressure gauge. Allow wall time and event time.

### 3.4 Topology strip

Display point-in-time:

- curve -> migration -> pool/route graph;
- duplicate/coin-family alternatives;
- typed wallet/social evidence edges;
- provisional territory membership; and
- edge validity/knowledge/revision.

Later-discovered edges are visually separate in retrospective replay.

### 3.5 Response/operator panel

Only after H3 gates:

- exact deterministic protocol component;
- observed residual response by state and lag;
- simple baseline prediction;
- fitted operator with calibration/support;
- uncertainty and negative-control status; and
- label `observed/fitted`, never `caused`.

### 3.6 Episode overlay

Overlay operator scene and inventory path:

```text
surface -> viewport -> inspect -> arm -> entry -> partial -> runner
        -> exit -> flat watch -> re-entry -> resolution
```

The same market field can have different meaning under retain, reduce-only, watch-flat, competing
SOL opportunity, or unresolved stance. Operator axes remain visible.

## 4. Formal research sequence

### F0 — settlement closure atlas

**Question.** Can exact asset conservation close across controlled wallets, Pump/PumpSwap actions,
LP positions, internal transfers, fees, rent, rewards, and migration?

**Inputs.** Finalized balance/account effects, transaction locators, asset identities, token
programs, boundary manifests, and decoder/reconciler versions.

**Estimand.** Atomic residual `epsilon_a^B` by asset, event class, profile, and source.

**Adversarial cases.** Nested boundaries, wrapped/native SOL, Token-2022 fee/withheld semantics,
inner instructions, unknown incoming basis, dust, failed attempts, LP claim/remove.

**Continue if.** Exact closure holds for the scoped fixtures or defects are explicit/refusing.

**Stop policy work if.** Residuals are unexplained or correlated with high-activity/tail states.

**Useful residue.** Financial forensic/reconciliation tool.

**Rung.** H0.

### F1 — venue geometry and quote atlas

**Question.** What are the exact directional size-cost/capacity surfaces for Pump, PumpSwap, and
Meteora states, and how do marks, quotes, fills, and liquidation differ?

**Inputs.** Coherent profile-bound account closure, fee/token rules, exact calculator, state/route
clocks, simulation/comparator, and landed fills.

**Estimands.** Quote/fill error, finite-size cost, capacity, refusal boundary, exact-versus-smooth
error, and landing-state displacement.

**Adversarial cases.** Atom/rounding edge, fee tier, real versus virtual reserve, one-bin boundary,
dynamic fee, stale state, route fork, same-slot competitor.

**Continue if.** Error is well below the intended economic hurdle for one scoped size/venue.

**Stop predictive micro-profit work if.** Geometry/profile/landing uncertainty consumes the edge.

**Useful residue.** Executable exposure and liquidation glass.

**Rung.** H1/H2.

### F2 — liquidity and LP inventory measures

**Question.** Which exact/discrete measures describe current executable capacity and a position's
contingent inventory without hiding asset composition?

**Inputs.** Exact quotes across sizes, DLMM per-bin state/shares/checkpoints, add/remove/claim events,
routes, dynamic fees, and withdrawal/liquidation quotes.

**Estimands.** Capacity surface, active-bin distance, per-bin X/Y entitlement, concentration,
withdrawal value, full leg liquidation, and fee/selection/inventory waterfall.

**Falsifier.** A compressed density or scalar score changes conclusions relative to exact bins and
quotes, or unsupported accrual/operation fields matter materially.

**Continue if.** The field makes unwanted conversion, capacity, or rebalancing consequence easier
to understand and predict prospectively.

**Shelve field compression if.** Exact native geometry is already clearer.

**Useful residue.** LP truth surface and action comparison.

**Rung.** H1/H2, with H3 only for prospective response.

### F3 — marked flow and memory atlas

**Question.** What persistence and cross-event structure exists in signed AMM flow, liquidity edits,
wallet acts, and lifecycle strata?

**Inputs.** Market-wide compact census plus hot-scope detail, direct sign/user roles, exact size,
venue/lifecycle, wall/event clocks, and coverage.

**Estimands.** Conditional sign ACF, transition hazards, actor-splitting versus broad-flow
components, state-conditioned forecast gain, and regime drift.

**Baselines.** IID, seasonal count model, Markov/DAR, shuffled-within-state, and cold-market stratum.

**Falsifier.** Gain disappears under participant, lifecycle, source-health, or attention-selection
controls, or does not replicate chronologically.

**Continue if.** The structure improves flow/state forecast or materially informs glass even when
return forecast remains weak.

**Rung.** H2/H3.

### F4 — launch/migration topology accounting

**Question.** Can JOSHI preserve asset, venue, route, family, and price-object continuity across
launch/completion/migration without inventing a smooth series?

**Inputs.** Creation/migration transactions, curve/pool state, route assertions, family evidence,
and bitemporal knowledge.

**Estimands.** Topology-map completeness, asset pushforward residual, route availability, splice
uncertainty, and time-to-executable post-migration state.

**Falsifier.** Canonical association requires later knowledge, multiple routes remain unresolved,
or asset/state map does not close.

**Continue if.** Lifecycle-aware panels/studies avoid real misclassification and reveal opportunity
or risk.

**Useful residue.** Correct coin/venue history even if no topology model predicts returns.

**Rung.** H0–H2.

### F5 — wallet/social multiplex flow

**Question.** Do typed wallet and social layers reveal candidate discovery, community transition,
or territory movement beyond anonymous market flow and product ranking?

**Inputs.** Direct signed users, profile/follow mappings, posts/replies/stable IDs, fee claims,
family membership, actor evidence, point-in-time joins, and complete source health.

**Estimands.** Earliest-source lead time, identity-over-flow increment, repeat-participant movement,
family audience share, claim/participation competing hazards, and operator inspect/arm response.

**Negative controls.** Unrelated mints, platform-wide bursts, future-shifted social events, anonymous
flow matches, alternate family maps, and resolver permutations.

**Falsifier.** Generic graph embeddings win only through later identity/family joins, wallet IDs add
nothing beyond public flow, or directed audience movement collapses to common rotation/coverage.

**Continue if.** The typed graph repeatedly surfaces a relevant rival/transition earlier or improves
operator understanding at tolerable burden.

**Useful residue.** Evidence-oriented identity/family strip.

**Rung.** H2/H3; controller/entity/community explanations remain H4.

### F6 — observed response and resilience

**Question.** After exact instantaneous protocol geometry, how do price, quote capacity, liquidity,
and activity respond to marked events across lag and state?

**Inputs.** Exact pre-state, marks, multiple price/quote objects, subsequent state, coverage,
same-slot order, lifecycle, and product/social context.

**Estimands.** Deterministic-adjusted observed response, linear-kernel forecast, state-dependent/
history-dependent challenger, expected-versus-surprising flow response, and tail route-loss event.

**Falsifier.** Kernel is unstable, a simple state baseline matches it, residual is below alignment
error, or causal language is required to make it seem useful.

**Continue if.** Held-out calibration/forecast improves at an attainable size/horizon or reliably
marks state fragility.

**Useful residue.** Response surface with exact uncertainty.

**Rung.** H2/H3; reaction impact remains H4/counterfactual.

### F7 — attention compression and scale dilution

**Question.** How do candidate mass, observation fidelity, operator attention, and incremental value
change as scope expands?

**Inputs.** Census/surface/render/viewport/open/arm sets, rank/order, UI version, hot-scope resources,
attention time, matched shadow outcomes, and portfolio/capacity.

**Estimands.** Funnel transition rates, value per attention hour, first/next-k marginal value,
high-resolution coverage selection, and total value/capacity/tail burden as breadth grows.

**Falsifier.** Apparent gain is just high-coverage/surfaced selection, panel-induced behavior, or
machine extrapolation beyond Ember's expressed ranks.

**Continue if.** The apparatus routes attention more effectively without drowning Ember or erasing
the original Pump-like information surface.

**Useful residue.** Honest source/product/attention observability.

**Rung.** H2/H3; a ranking controller is H5.

### F8 — composite episode operator

**Question.** Can field/graph context help Ember's crackle, runner, exit/flat/re-entry, fancoin, or LP
management process after selection and execution are kept separate?

**Inputs.** Scene manifest, disposition axes, exact quotes/fills/ledger, field artifacts visible at
the time, operator acts, alternatives, common horizon, and liquidation.

**Estimands.** Selection uplift, entry timing, partial/runner contrast, exit/re-entry cycle,
opportunity/capital-time, and UI-assistance value.

**Falsifier.** Advantage vanishes with full residual valuation/common horizons, depends on
retrospective field construction, or the UI changes behavior without improving bounded outcomes.

**Continue if.** A small field panel becomes a naturally used, replayable instrument that improves
decision quality or information gain before profit is proven.

**Rung.** H2/H3 assistance; any policy imitation/advice is H5.

## 5. Strategy-family consequences

### 5.1 Crackle

The useful field is not a “dip pressure” scalar. It is a bundle:

```text
exact directional quote/capacity surface
recent marked signed flow and participant evidence
state/route/fee/latency regime
observed response and resilience uncertainty
operator nomination scene and expiry
```

The first falsifier remains economic: the apparatus and transaction hurdle must be smaller than the
target crackle. Persistent flow can make a microdip continue rather than revert.

### 5.2 Retained runner

Use exact inventory plus size-specific liquidation and territory/community concentration. The
runner's mark, full liquidation, retained upside, remaining basis, and correlated exposure stay
separate. A “potential well” metaphor adds nothing.

### 5.3 Exit, flat watch, and re-entry

The operator episode is the slow behavioral topology; inventory epochs are exact settlement
intervals. Flatness can preserve attention/thesis and later re-entry. Field state shown during the
flat interval must be in the as-known scene if credited to the decision.

### 5.4 Fancoin/social transition

Use a multiplex temporal graph and competing transition hazards. Creator awareness, fee claim,
participation, endorsement, audience arrival, and community persistence are distinct marked events.
Do not call audience growth a phase transition unless the severe gate in
[`ANALOGY_REDTEAM.md`](ANALOGY_REDTEAM.md#10-criticality-and-phase-transition-theater) is met.

### 5.5 Meteora LP

The LP is a discrete commodity-valued measure over bins plus a contingent swap schedule. Use exact
withdrawal and both-leg liquidation before any smoothed liquidity field. A rebalance hypothesis
must specify whether it is add/remove, in-place reweighting, close/reopen, or swap-assisted
conversion; the current interface's limits are product facts, not protocol impossibility.

### 5.6 Whole Pump-like surface

A market-wide field without the actual ranking/feed/social/viewport surface observes a different
policy. Preserve compact census and choice sets first. Hot scopes are adaptive probes whose
selection boundary must remain visible in every field estimate.

## 6. Non-gameable promotion matrix

| proposed promotion | required win | dishonest way it can appear to win | blocking check |
| --- | --- | --- | --- |
| H0 settlement | exact closure | omit fee/unknown accounts or round residual | raw pre/post effects and nested-boundary fixture |
| H1 venue operator | atom/profile conformance | compare only friendly sizes or one SDK | boundary goldens, simulation, finalized effects, alternate oracle |
| H2 field | replayable descriptive utility | select hot/high-coverage successes | census denominator, source-health strata, frozen transform |
| H3 kernel/hazard | chronological calibrated gain | future joins, regime leakage, tune lags after outcome | availability cutoff, negative controls, predeclared lag/state grid |
| H4 latent state | narrows useful equivalence class | semantic label after seeing outcome | prospective emission definition and alternative topologies |
| H5 assistance | natural decision/information improvement | UI induces action then labels it validation | UI version/exposure logged; hidden/crossover comparison |
| H5 economic policy | full attainable-path advantage | marks, peak exits, survivors, frozen futures | fills/fees/failures/liquidation/common horizon/capacity/tails |

## 7. Stop conditions that preserve useful artifacts

Stop or demote a field/operator when:

1. its domain/units cannot be stated without metaphor;
2. exact protocol mechanics explain the apparent structure;
3. effect is below quote, fill, clock, or source uncertainty;
4. hot-scope/product selection creates the pattern;
5. point-in-time joins are unavailable;
6. topology/lifecycle changes dominate the supposed dynamics;
7. held-out results fail across sessions/regimes;
8. a generic graph or scalar loses distinctions Ember actually uses;
9. the visualization changes behavior more than it improves decisions;
10. scale/capacity/correlated tails erase the advantage; or
11. the model requires causal vocabulary unsupported by the design.

Preserve, respectively:

- exact ledger and reconciliation;
- quote/capacity/liquidation glass;
- source/coverage atlas;
- topology and point-in-time evidence;
- native flow/attention panels;
- replayable scenes and operator annotations; and
- negative/contradiction fixtures.

Failure of a grand field model can leave a much better cockpit.

## 8. Open formal questions

1. What is the smallest cross-venue interface that preserves native geometry while permitting
   quote/capacity comparison?
2. Which common coordinate—size fraction, cost displacement, log price, or something
   lifecycle-specific—supports comparison without hiding route/fee boundaries?
3. Can migration be represented as a partial typed pushforward with useful residual diagnostics?
4. What exact transaction/bundle evidence is sufficient to separate deterministic focal movement,
   competing pre-landing movement, and post-landing response?
5. Which participant identity uncertainty representation is honest enough for signed-flow memory?
6. Does a state-dependent event kernel add anything over exact reserve/bin state plus simple recent
   flow?
7. How should the attention domain represent simultaneous cards/panels without inventing conserved
   cognitive mass?
8. Which family/territory relations are stable enough for graph flow, and which should remain
   retrieval-only assertions?
9. Can exact DLMM bin measures reveal a reusable local risk coordinate without smoothing away the
   active-bin boundary?
10. What prospective probes distinguish social transition from price/platform common cause without
    randomizing capital?
11. How quickly do fitted operators drift after JOSHI changes the surface or Ember's workflow?
12. Which useful policy questions are only partially identified, and what bounds are decision-
    sufficient?

## 9. Concrete questions for existing JOSHI lanes

### Episode/accounting

- Can every field shown at a decision be linked to the exact scene and knowledge cutoff?
- Does the episode remain continuous while topology, venue, and inventory epochs change?
- Which value projections are additive, and which share route/capacity constraints?

### Event tape/sources

- Can every zero be tied to healthy scoped coverage?
- Are compact events sufficient to reconstruct exact marks and pre/post state?
- How will dynamic domain/topology manifests survive retention and decoder revision?

### Social/ecology/wallets

- Are graph edges typed, bitemporal, and layer-specific end to end?
- Can later identity/family joins be mechanically excluded from as-known artifacts?
- What negative-control population challenges directed audience/wallet movement?

### Crackle/execution

- Is intended-size quote/fill error below the target crackle across tail latency states?
- Which field artifacts existed at arm time and which are retrospective?
- Does same-slot ordering make a proposed trigger observationally late?

### Portfolio/LP

- Can exact per-bin inventory and withdrawal close before valuation?
- Does the candidate compression preserve both asset legs and route capacity?
- Are fee income, inventory conversion, rebalance, and opportunity cost separate fluxes?

### Estimation/learning

- Which rung and causal status does each target occupy?
- What gauge/equivalence transformations should leave the conclusion stable?
- What simple venue/state baseline must a learned operator beat?
- How will UI/model exposure define a new composite-policy regime?

### Product glass

- Can authority rung, source gaps, exact native geometry, and uncertainty remain visible without
  overwhelming the operator?
- Which physics terms can be removed from labels entirely?
- Does the panel support Ember's distinctions rather than forcing one universal market state?

## 10. Recommended immediate order

1. Finish F0 settlement closure and F1 exact quote/fill geometry.
2. Build F2 exact DLMM/route measures and the conservation/exposure glass.
3. Use F3 descriptive marked-flow panels before fitting memory kernels.
4. Establish F4 point-in-time lifecycle topology and F5 typed graph projections.
5. Attempt F6 kernels only on scopes that pass state/coverage/error gates.
6. Measure F7 attention and UI feedback as the product evolves.
7. Evaluate F8 composite episodes before promoting any learned policy.

The field model should grow only where the previous rung leaves a specific residual question. It is
not a mandate to build a universal simulator.
