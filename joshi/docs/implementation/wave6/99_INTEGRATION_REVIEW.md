This is a ceiling ledger, not a green-test summary. In this review:

- `design_only` means a document specifies a future contract or campaign but no executable
  occurrence closes it;
- `intrinsic_contract` means pure code validates or transforms caller-provided values;
- `fixture_recovered` means deterministic checked-in/synthetic examples exercise that code;
- `store_resolved` requires the sole store to derive identities, clocks, cutoffs, evidence and
  receipts rather than accepting their spellings from the caller; and
- `prospective` requires frozen enrollment/assignment, complete denominators, later maturation or

`universe_complete`, `manifest_id`, `coverage`, `outcome_visible = false`, or authority literal is
not a receipt or evidence occurrence.

## Blocking findings

### W6-B0 — the prototypes cannot author their own Wave 6 entry gates

The master plan correctly makes the current Wave 5 gates external evidence occurrences. None of
the three packages consumes a store-resolved `W5-G*` occurrence or a Wave 6 program/campaign
registration. All are pure public constructors over caller material.

This is honest while the outputs remain fixtures. It becomes a blocker wherever implementation
prose calls a caller row “registered,” “witnessed,” “complete,” “known,” “exact,” or “common”
without adding “as asserted by this input.” In particular:

- response occurrence IDs, version IDs, coverage windows/gaps, availability clocks and commit
  sequences are supplied in Arrow rows;
- shadow-policy evidence digests are checked for SHA-256 syntax but not recomputed from evidence,
  and its policy/plan registration is proved only by supplied timestamps; and
- routed `universe_complete`, coverage, candidate IDs, scenario identity, terminal manifest ID and
  external unwind are supplied directly.

**Ceiling:** all positive results remain `intrinsic_contract` or `fixture_recovered`, even when the
input happens to have come from a real market. A later adapter must not promote by copying these
fields into a private constructor; it must resolve and bind the exact store occurrences.

### W6-B1 — future-byte, presence and cross-relation attacks repaired

Cutoff selection now precedes semantic validation. The exact original attacks pass: invalid wholly
future response and risk bytes are invariant to physical absence. R1 also passes: a current anchor
missing one component returns the identical `CoverageError` both without the row and with that row
present only after cutoff.

A risk row is now semijoined only to response anchors admitted at the same cutoff. The stronger
pair therefore also passes: keeping a known-but-invalid risk row while supplying versus physically
removing its wholly future response anchor yields byte-identical response, risk and refusal tables.
At a later cutoff the anchor enters support and the invalid label is then explicitly refused:

```text
future_only_vs_physical_removal True True True 0 0
later_cut_validation 1 2 0 1 unregistered_competing_event_kind 16
```

**Ceiling:** PASS for every reproduced no-future-input adversary at `fixture_recovered`. A
point-in-time or release-reproducible operational artifact remains BLOCKED only because the cutoff,
availability clocks, relations and identities are not store-resolved.

### W6-B2 — response identity, pending denominator and R2 failure isolation repaired

Response identity now hashes only eligible response observations, and risk output has its own
identity. Changing a valid known terminal label changes risk output while leaving response rows,
cell IDs and digests byte-for-byte equal. Eligible response anchors with no known outcome now
remain as explicit pending subjects: the probe emitted three context rows, each with cohort `2`,
known `0`, pending `2`, and two pending subject IDs.

Known invalid risk input no longer vetoes the response result. R2 returns the byte-identical
response surface, no risk cells and one deterministic typed risk refusal:

```text
R2_invalid_label_isolated True 0 1 unregistered_competing_event_kind
```

**Ceiling:** PASS for independent response identity, local pending denominator and invalid-label
failure isolation at `fixture_recovered`; BLOCKED for store-resolved releases and for incidence,
hazard, probability, calibration or an outcome-complete nonfixture atlas.

### W6-B3 — exact fixture arithmetic repaired

Authoritative response output now carries a decimal-string sum and a reduced rational mean rather
than a binary float. The original `2**53`/`2**53 + 1` half-atom case is exact, and aggregating six
signed-`int64` maxima uses Python's arbitrary-width accumulator without overflow:

```text
exact_rational_mean 18014398509481985 True 18014398509481985/2
wide_accumulation True True 1
```

**Ceiling:** PASS for exact aggregation and means over the declared signed-`int64` fixture input
domain. The source schema remains `int64`, and store-resolved wide input admission is not present;
this does not raise the overall atlas above `intrinsic_contract / fixture_recovered`.

### W6-B4 — strict valuation shape repaired; source occurrence remains caller-authorable

Starting valuation now carries clocks, commit order, evidence closure/digest, method and typed
known/refused status. Each known value requires a closed source kind/method, exact unit and
whole-holding input/output, recomputable integer ratio, content-derived wrapper digest and strict
source-before-valuation-before-decision order. Numeraire inventory uses exact 1:1 identity; typed
refusal makes PnL/opportunity arithmetic unknown.

The requested attacks fail closed: an arbitrary known method label, a component amount differing
from its artifact output and a source commit tied with the valuation commit are rejected. A valid
ten-token-to-50-numeraire artifact yields starting `1050`, terminal `1060`, PnL `10`.

The source occurrence itself is not resolved. A caller can provide an uncertified carrier and
SHA-shaped source digest, choose a self-consistent 1:1 token/numeraire ratio, and obtain a different
scalar while still satisfying the intrinsic contract:

```text
residual_caller_authored_source_bytes complete 1010 1060 50 caller:uncertified-exact-route
```

**Ceiling:** PASS for strict shape, recomputation and order at `intrinsic_contract /
fixture_recovered`; BLOCKED for economic starting value, `net_pnl_numeraire_atoms`, candidate
surplus or opportunity cost until the source artifact/carrier is store-resolved.

### W6-B5 — shadow terminal and LP one-sided-gain attacks repaired

A projected positive-input shadow terminal disposal now requires positive exact numeraire output;
the original zero-output quote is rejected. LP actions carry event/position/install identities and
reconciled principal/fee/cost components. Flow before a successful install is a typed
`illegal_policy_transition`, and the old one-sided `+10` flow fails the give/receive principal
contract. A separately valid two-sided pre-install flow was refused with no effect and unchanged
fixture PnL.

The routed terminal attack is also repaired: a full-size quote with zero net output now produces a
`partial` liquidation, no scalar, and residual reason `nonpositive_net_output`.

**Ceiling:** PASS for the two exact shadow attacks at `fixture_recovered`; BLOCKED for exact
portfolio, routed-policy, fee, terminal-value or PnL evidence because all quote/effect occurrences
remain caller-authored.

### W6-B6 — shadow self-fee posting repaired; cross-lane optionality remains unqualified

LP accounting evidence now separates route principal, external fees/costs and zero-sum household
self counterlegs, then reconciles the posting balance delta. The original self-owned fee embedded
as a positive posting effect is rejected:

```text
original_self_fee_posting ManifestError:liquidity accounting components do not reconcile to quote effect
```

The routed reducer-generated household path now records the paired counterparty deltas, so its
local fixture consolidation cancels owned self-flow and leaves protocol cost. The public DTO now
requires retained counterlegs and exact fee/counterparty reconciliation: the unpaired fee and a
wrong counterparty delta reject, while an exact counterleg is accepted.

The ITR/LVR helpers now require the run's frozen family. The audit rejects a missing required
diagnostic, both diagnostics and a diagnostic from a differently named scenario. It also
recomputes and binds a scenario-policy content digest and a registered-input/run digest rather than
trusting the display label. Exact runtime-family checks reject an ITR object in the LVR slot and an
LVR object in the ITR slot. Independent same-label/different-policy and
same-label/different-registered-run probes reject, while exact ITR and LVR attachments pass.

There is still no shared store-resolved run artifact preventing downstream narration from
combining fees, terminal branch differences, ITR/LVR-like values and opportunity surplus.

**Ceiling:** PASS for shadow/routed self-fee non-posting and all reproduced attribution identity,
family and exclusivity checks at `fixture_recovered`; BLOCKED for consolidated household surplus,
operational adverse-selection reporting, external-service revenue, optionality value or a joint
spot/LP comparison because registration and evidence remain caller-authored rather than
store-resolved.

### W6-B7 — same-time shadow commit order repaired

Execution quotes must commit after their own decision and sort strictly before the next decision
under `(available_at, commit_seq, occurrence_id)`. The original quote available at the next
decision time with later commit `30` is rejected before replay.

**Ceiling:** PASS for deterministic fixture tape ordering, including tied timestamps. The clocks
and commit sequences remain caller-authored, so no store-resolved chronological replay claim.

### W6-B8 — incomplete denominator and synthetic slot stamping repaired

Complete-universe assertions now require observed-complete coverage. Missing witnessed candidates
and absent successful baselines produce typed unknown decisions with no baseline scalar, margin,
selection or state transition. The original source-gap/zero-baseline activation is rejected at
the witness contract, and its observed-complete missing-candidate variant returns
`unknown_missing_candidate`.

State edges, Jupiter witnesses, observed venue quotes and would-quotes now retain an exact
`SourceCut` containing cut ID, slot, profile and topology epoch. Reference and ghost cuts at slot
`99` against Jupiter slot `101` both return `unknown_incompatible_source_cut`, no selection and no
modeled transfer; the reference quote retains slot `99` rather than being stamped `101`.

**Ceiling:** PASS for no-zero-substitution and exact local cut compatibility at
`fixture_recovered`; BLOCKED for a store-resolved coherent cut, complete-universe,
activation-margin or route-competitiveness observation because each cut/candidate assertion is
still caller material.

### W6-B9 — routed latency/unit attacks repaired by typed refusal

Arbitrage now carries explicit input/output/unwind/cost/profit asset IDs and requires the latter
three to use the input asset. A direction/unit mismatch refuses. Arrival slot is request plus
registered latency; because no later state is available in this fixture reducer, every nonzero
latency refuses as `latency_state_unavailable` instead of acting immediately. Both latency `1` and
`1_000_000_000` left inventory unchanged.

**Ceiling:** PASS for unit consistency and no-immediate-action at `fixture_recovered`; BLOCKED for
an actual temporal response, arbitrage feasibility or modeled-profit observation. Unwind values and
state chronology remain caller inputs.

### W6-B10 — routed transition and terminal content attacks repaired

`DlmmBinEdge.apply` recomputes the exact quote from current state and requires complete equality;
the forged 400-for-1 quote is rejected. Terminal manifests require unique occurrence IDs and
asset/size keys, canonical order and a recomputed full-content SHA-256 digest. Branch comparison
requires byte-identical manifest content, so two different quote sets sharing one caller label no
longer produce surplus.

**Ceiling:** PASS for exact fixture transition/manifest identity. BLOCKED for a durable common
terminal occurrence or empirical transition witness because state/quote/manifest inputs are not
store-resolved.

### W6-B11 — topology, identity and deterministic occurrence closure are uneven

The response prototype at least groups by lifecycle/topology/context version IDs and validates
shared lifecycle/caller/topology availability intervals. It still has no resolver occurrence or
content digest, and wallet/cluster version IDs do not have independently typed validity and
availability histories.

The shadow arena has no venue/profile/topology epoch at all. Routed state now binds a caller
`SourceCut` with slot, profile and topology epoch and refuses unequal cuts. It still has no
store-issued observation/knowledge occurrence, retraction history, capability occurrence or
transition map. None can consume a later identity/topology correction without an ad hoc new input.

Shadow record IDs use only the first 32 hex characters of SHA-256 and have no collision check or
full per-record digest. Routed terminal quote IDs are now unique and terminal content is fully
digested, but source-cut, witness, state and scenario IDs remain arbitrary strings. These are
deterministic on the happy fixture but not safe global occurrence identities.

**Ceiling:** no cross-release lineage, topology pushforward, identity revision or durable
idempotence claim.

### W6-B12 — lane-local claim disclaimers pass; empirical profit/causal language still does not

The strongest PASS is semantic restraint. The code and documents repeatedly distinguish:

- response association from caused impact or strategy;
- policy action from quote, hypothetical effect, transaction, fill and landed effect;
- would-quote from observed quote, modeled route from Jupiter route, and modeled transfer from
  landed fill; and
- terminal branch arithmetic from future expected value.

Those literals are necessary and should remain. They do not repair the counterexamples above.
Fields named `net_pnl`, `candidate_surplus`, `modeled_profit_atoms`, activation margin and LVR-like
value may be shown only as assumption-bound fixture arithmetic. There are no support denominators,
prospective cohorts, calibration estimates, causal designs, router parity observations, terminal
landing calibration or household effects behind them.

**Ceiling:** PASS for explicit non-claim language; BLOCKED for causal, profit, strategy, advantage,
calibration, usefulness or economic reporting.
